# Decisions, Assumptions, and Open Questions

## Decisions already made
- Product name: HeatSense.
- Initial geography: India, followed by global expansion.
- Forecasts: generated by HeatSense-trained model(s); external forecast values are not silently substituted.
- Horizons: +24 hours and +48 hours.
- Spatial output: detailed regional grid maps, constrained by actual source/model resolution.
- UX: animated globe/camera travel to selected country/state/city.
- Frontend: React + TypeScript.
- Backend: FastAPI.
- ML: Python, scikit-learn, Random Forest, XGBoost, baseline model.
- Mapping candidate: CesiumJS; verify provider requirements and licensing.
- First work package: architecture and repository skeleton, followed by a small data feasibility pilot.

## Assumptions to verify
- ERA5-Land access and selected variables are appropriate for the chosen date range and region.
- The selected data provider permits the intended usage and redistribution/derived outputs.
- A 24/48-hour ML-only forecasting strategy can achieve useful skill without external forecast inputs.
- CesiumJS and the chosen base imagery/terrain configuration can be used within budget and provider terms.
- A local file-based data store is sufficient for the MVP.

## Must be resolved by the Lead before implementation locks
1. Exact Python and Node versions supported by selected dependencies.
2. Dataset access workflow and license/attribution.
3. Initial pilot region and time range.
4. Forecast initialization schedule and expected data freshness.
5. Exact inference strategy for +24h/+48h without external forecasts.
6. Whether to model hourly temperature or daily max/min in addition to hourly target.
7. Whether risk layer is included in MVP or deferred.
8. Map basemap/terrain provider, token, and terms.
9. Hosting target and budget.
10. Whether a database is necessary after performance measurement.
